# 运行时开关必须保留逃生通道：关闭态仍可读写开关自身

> 提升日期：2026-08-21 ｜ 来源：PR #118 集群实测（hello-k8s-ai-dev）｜ 适用对象：本地 Agent / 远程 AI
> 触发条件（Use when）：实现"运行时开关 / 停用"类功能时；面板开关类 API 设计时；部署后功能验证时

## 现象

- AIOps 运行时开关（`enabled`）关闭后，`GET/POST /api/v1/aiops/settings` 被 `requireAIOps` 门禁一起 404（`AI_OPS_DISABLED`），用户无法在面板重新打开开关，只能重启后端恢复默认启用态。
- 单元测试全绿（测试只覆盖了 jobs 404），**集群实测才发现**：关闭 → 设置页打不开 → 无法恢复。

## 根因

- 把开关状态并进全局路由门禁（`requireAIOps` 加 `!Enabled()`），却没有给"开关自身的读写端点"豁免；
- 测试只验证了"关闭后业务接口被拦"，漏了"关闭后如何恢复"这一半闭环。

## 对策（必须动作）

1. 开关自身的读写端点（settings）**不走启用门禁**：关闭态必须可读可写，否则开关不是开关，是自杀按钮；
2. 部署后实测**完整闭环**：关 → 业务接口 404 → 开关仍可读 → 开 → 业务接口恢复 200；
3. 测试同时覆盖两个方向：关闭后业务 404 + 关闭后 settings 仍 200/可恢复。

## 证据链

- PR #118（AIOps 运行时开关）；`server_routes_test.go` TestAIOpsSettingsReachableWhileDisabled；集群 curl 闭环验证输出。
