# 一切皆异步：禁止空转等待

> 提升日期：2026-08-19 ｜ 来源：#71 升级验证与集群恢复过程 ｜ 适用对象：本地 Agent
> 触发条件（Use when）：任何预计超过 30 秒的阻塞等待（CI / 集群 / 构建）时

## 现象

- 集群恢复等 API Ready 时连续空轮询 5+ 分钟无输出，用户只能盯着看。
- kubectl EOF 排查期间反复“等→查→等”串行，未并行推进其他任务。
- 等待预期时长未先查证（kind API 恢复实际 1-3 分钟，却按 10s 间隔盲等 15 分钟）。

## 根因

- 把阻塞等待当成“当前唯一任务”，没有并行任务队列。
- 未从历史文档（15/32/34 号、change-history）与网络先确认“大概多久能好”。

## 可复用规则

- 等待 >30s 前先查证预期时长，并列出等待期间的并行任务（至少 1 件）。
- 长等待一律 `setsid nohup ... > log 2>&1 &` 后台化 + 日志落盘，前台做不依赖其结果的事。
- 轮询间隔按预期时长定：1-3 分钟预期 → 10-20s；10 分钟预期 → 60s；不高频空转。
- 故障排查用“分侧二分”一次测完：Windows curl / WSL curl / 容器内 curl。
- 向用户汇报“等什么 / 预计多久 / 期间在做什么”，不等用户催。

## 验证方法

- 任一长等待任务：检查是否存在并行任务、是否先查证过时长、等待期间是否有进展输出。
