# 远程 AI 交付模板

> 维护层：remote ｜ last-reviewed：2026-08-18 ｜ 适用：每次产出按本模板组织

## 标准交接格式

```text
标题：<任务名>（<日期>）
结论：<一两句话>
依据：<包内文件路径列表>
交付物：<报告 / diff / 文档片段>
未验证：<逐项列出与原因>
给 Agent 的落地建议：<本地 Agent 执行时的注意点>
```

## 每类交付物要求

### 报告（方案 / 审查 / 排障）

- 结论先行的摘要表（问题 → 推荐 → 依据路径）。
- 每个结论附包内文件路径；推断标"推断"。
- 排障类必须列出"还需要哪些证据"（日志、命令输出），不假装定位。

### Diff（写代码类）

- 只给任务范围内的改动；逐文件说明改了什么、为什么。
- 头部注明基线（`CONTEXT_PACK.md` 的最近提交）与目标分支假设。
- 标注未验证项（未编译/未测试/未跑 lint），并给出本地 Agent 应运行的验证命令。

### 文档片段（写文档类）

- 标明目标读者分层（人类 / 本地 Agent / 远程 AI）与建议放置路径。
- 与现有 front-matter 风格一致（`维护层 | last-reviewed | 事实源`）。
- 不跨层复制大段内容：一个概念只给一个主文档，其他位置用链接。

### Issue 草稿

```text
标题：<类型前缀：design: / feat: / fix: / docs:> <一句话>
描述：
- 问题描述（现状与影响）
- 期望状态
- 修改方向
- 验收标准
优先级：P0/P1/P2 建议 + 理由
```

## 自检清单（交出前逐项勾）

- [ ] 结论在第一段，依据引用包内路径。
- [ ] 所有"未验证"都显式标注并说明原因。
- [ ] 没有假装访问过 GitHub / 集群 / 数据库。
- [ ] 没有建议手改生成文件或绕过权限校验。
- [ ] CRD/API 结论核对过 `FIELD_OWNERSHIP.md`；时间语义核对过 `TIME_AND_REPLAY.md`。
- [ ] 文档与源码不一致处已作为交付物列出。
- [ ] 已扫 [PITFALLS.md](PITFALLS.md)，没有踩已知坑。
