# WSL 升级验证实验：2.9.4 预览线仍复现，环境已回滚（#71/#63）

> 日期：2026-08-19 ｜ 关联：Desktop/WSL 34 号文档、31 号（版本缺陷区间）、32 号（探针基线）、19 号 3.2（回滚指南修正）

## 为什么做

- #71：升级 WSL 2.9.5+ 重跑 port0 探针，验证端口 0 注册失败窗口消失 = 版本缺陷区间实锤。
- #63：Preview 跨版本复现测试（本实验并入执行）。

## 执行路径修正（源码级证据）

- GitHub compare 验证：**#41051/#41125 均不在 2.7.12**（最新 stable，diverged）；**均在 2.9.5**（ahead）。
- 结论：stable 通道必然仍复现 → 直接走 Preview 通道（`wsl --update --pre-release`）。

## 结果

- 安装 2.9.4.0（预览通道当前版本；2.9.5 tag 存在但无 release 资产，Store 未推送）。
- 探针：8 轮 ok=2/8；定量 40 轮 ok=5/40（12.5%），STALL 87.5%（2.7.8.0 基线 91.5%，同区间）；固定端口对照 3/3 OK。
- **结论**：2.9.4 不含 #41051/#41125（DLL 07-09 构建）→ 窗口仍在。版本范围声明扩展至 2.9.4（预览线）。
- 2.9.5+ 验证闭环待 Store 推送（每日只读监控已挂入 CodexWatch41286 计划任务）。

## 回滚踩坑（已实测，修正 19 号 3.2）

- `Add-AppxPackage` 只更新 Store 身份，**不替换 `C:\Program Files\WSL\` 二进制**（该目录由 MSI 组件管理）；必须再装同版本 x64 MSI 才完成文件层回滚。
- 流程：Appx 冲突 0x80073D06 → 移除 → 重装需管理员 0x80073D28（UAC）→ 补装 MSI → `wsl --version` 回到 2.7.8.0、DLL sha256 与升级前完全一致（3044acea...）。

## 验证

- 升级前后 DLL 指纹、内核版本、探针结果全部落盘：`Desktop/WSL/logs/wsl-upgrade-2026-08-19/{before,after}.txt`。
- 环境恢复：WSL 2.7.8.0 / Docker Desktop 29.7.2 / kind 5 节点容器 Up（API 恢复中，见 cluster-restore.log）。

## 回滚

- 本条目为实验记录，无代码改动。若 2.9.5+ 验证后需回到 2.7.8.0：按 34 号文档第四节流程（MSI 覆盖安装）。
